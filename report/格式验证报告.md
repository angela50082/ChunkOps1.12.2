## 3. 关键格式事实（实测，编码时以此为准）

```
chunk NBT 根      { Level: Compound, DataVersion: 1343, ForgeDataVersion: Int, <模组根级标签...> }
Level             { ForgeCaps, xPos/zPos, HeightMap: IntArray[256], Biomes: byte[256],
                    Sections, TileEntities, Entities, TerrainPopulated, LightPopulated,
                    LastUpdate, InhabitedTime, <模组 Level 标签...> }
Section           { Y: Byte, Blocks: byte[4096], Data: byte[2048](半字节), Add?: byte[2048](半字节),
                    BlockLight: byte[2048], SkyLight: byte[2048] }
legacy 索引       index = y*256 + z*16 + x
legacy 解码       id = Blocks[i] & 0xFF | (Add[i>>1] 半字节 << 8)（无 Add 则 0）
                  meta = Data[i>>1] 半字节；x 偶 → 低半字节，x 奇 → 高半字节（NibbleArray 语义，实测 7=基岩/1=石头/9=水/168=海晶石 吻合）
region 头部       4096B location 表 + 4096B 时间戳表；location = (起始扇区 << 8) | 扇区数
chunk 数据        4B 长度(含压缩类型字节) + 1B 压缩类型(1=gzip 2=zlib 3=none) + NBT
```

**实测解码示例**（`拔刀之旅\saves\流易斯` chunk(0,0)）：
- Y=0 层：`7:0` 基岩 ✅；Y=1：`363:5`（Add 数组高 ID 方块 ✅）；Y=3：`9:0` 水、`168:1` 海晶石 ✅
- TileEntities：`minecraft:mob_spawner`、`minecraft:chest`（**名称化** ✅）
- Entities：`battletowers:golem`（**模组实体名称化** ✅）
- chunk 根级模组标签：`cofhworld`、`forestry`、`Thaumcraft`、`MekanismWorldGen`、`NaturaWorld`、`thebetweenlands:chunk_data` 等（**复制粘贴必须携带**）

## 3.5 结构文件与原理图格式（清单 7/8 实测补充）

**1.12.2 结构方块文件（vanilla 结构格式，样本：`GreedyCraft2\addons\...\data\structures\additions\bismuth_cave.nbt`）**：

```
palette: List<Compound>  →  { Name: "modid:block", Properties?: { <属性名>: "<字符串值>" } }
blocks:  List<Compound>  →  { pos: [x,y,z] (Int x3), state: Int（palette 索引） }
size:    List<Int> x3
entities: List<Compound>
author:  String
DataVersion: 1343
ForgeDataVersion: Compound（19 个模组版本：mekanism/forestry/thebetweenlands/rftools/...）
```

- **palette 名称化 + Properties 字符串映射** → 跨模组集读取安全（属性语义需目标注册表支持）；`ForgeDataVersion` 记录了生成时的模组版本表（fingerprint 素材）。
- 设计影响：我们的 `.mcops` 采用同样的名称化理念（一致）；**结构文件导入导出可行**（Properties → 目标 `IBlockState` 需经模组注册表解析）。

**Schematica `.schematic` 原理图格式（样本：`GreedyCraft1.34\config\lucky_block\...\*.schematic`）**：

```
Schematic: Compound
  Width/Height/Length: Short
  Materials: String = "Alpha"（数字 ID 模式）
  Blocks: ByteArray（方块数字 ID）
  Data: ByteArray（数字元数据，半字节）
  Biomes: ByteArray
  Entities / TileEntities / TileTicks: List
```

- **纯数字 ID + 数字 meta**：同模组集内可用；**跨模组集转换必然串方块**（用户痛点的直接来源之一）。
- 设计影响：`.schematic` 导入按「当前实例注册表」解释数字 ID（与存档同源策略）；跨模组集请用 `.mcops`。

## 4. 对设计文档的影响（v0.2 → v0.3 修正点）

1. **§2.2/§3「palette 是 1.12 存盘格式」→ 修正**：1.12.2 存盘是 legacy 数组；palette 仅内存/网络。**对方案是利好**：legacy 数组解码简单、无位压缩；读取端仍保留 palette 兼容（自造样本已验）。
2. **§3 新增**：chunk 根级模组标签与 `ForgeDataVersion`、`Level.ForgeCaps`——跨世界复制/移动时**整份 NBT 原样携带**（只重映射方块/生物群系数字 ID）。
3. **§3 新增**：region 头部第二张表是时间戳（实现时勿当 size 表）；location 低 8 位是扇区数。
4. **§3 修正**：`Heightmaps`（复数）不存在，旧 `HeightMap` IntArray[256] 存在。
5. **§10 清单更新**：1–9 全部实测（7/8 见 §3.5），10–13 与阶段 1 项见 §6。

## 5. 额外发现（真实存档的脏数据）

- **region 头部索引损坏**：`新的世界\r.-3.1.mca` 等存在 location 指向越界（超出文件长度）的槽位，但对应数据区存在合法 chunk（疑似旧工具处理痕迹，用户机器上有 MCA Selector）。→ 读取器必须做越界保护并按「索引→数据区」双路径容错（verifier 已实现越界跳过 + 统计）。
- **同一存档混有旧版本遗留 chunk**：部分 chunk 为 legacy 格式且无模组标签（旧版生成、从未被 1.12.2 重写），部分为 1.12.2 时代生成（有 Add/模组标签）。→ 编辑器必须接受两种形态并存。
- **被区块工具清空过的世界**（`哭泣的黑曜石`，123,898 chunk）：全部 chunk 保留完整骨架（16 个模组根级标签、Sections、Biomes、HeightMap），但**方块全部为 air（id=0，实测 maxId=5）**——典型「区块清空/删除」操作痕迹（用户机器装有 MCA Selector，`E:\mc\MCA`）。→ 编辑器应能识别并提示「区块已被清空」。
- **`Biomes` 非标准形态**：同一存档的 `Biomes` 为 `IntArray[256]`（vanilla 1.12.2 写 `byte[256]`，对照存档流易斯为 byte[]），系外部工具（MCA Selector/Amulet 系）写回痕迹 → **读取端必须兼容 byte[]/int[] 两种形态**（verifier 已支持，写入时按目标世界既有形态保留）。
